# Phase 4 ローカル実装の検証計画

2026-10-08。承認されたローカル実装の検証計画。実行結果は `phase4-local-verification.md` を参照。外部依存追加、Google操作、本番公開、実応募データは対象外。

## 作業対象案

共通の認証・処理状態・版管理を保存アダプターから分離し、メモリ上の模擬保存先で試験する。フォームは既存の人数別入力・全体検証・確認画面を再利用する。Phase 3送信経路は変更せず、Phase 4検証入口を明示的に分離する。ブラウザの乱数生成と、保存側の検証を混同しない。

模擬保存先は認証・非公開履歴・共有表示の3領域とする。これは権限分離の動作モデルであり、実際のGoogle共有権限を検証できた意味ではない。保存アダプターは認証情報をブラウザへ返さず、画面操作から通常の認証境界を検証する。ブラウザのみで全領域を保持する試作は本番の秘密保護を再現できないため、認証検証はローカルサーバー側を候補とする。

## 確認項目

| 検証 | 期待結果 |
| --- | --- |
| コード生成不可 | 安全でない代替生成をせず送信を止める |
| コード未保存 | 送信へ進めない。未受付と明示 |
| 初回正常保存 | 3領域の整合後に受付番号・確定版を返す |
| 初回応答切断 | 同じコード・処理IDで同じ応募へ戻り、増殖しない |
| コード違い／番号不存在 | 同じ認証失敗応答。内容・番号の存在を返さない |
| 再送IDのみの照会 | 認証を省略しない |
| 同じIDで内容違い | 既存内容を差し替えず競合にする |
| 形式・人数変更 | 応募IDを維持。対象外の情報を除外し、全条件を再検証 |
| 5形式・チーム4／5／6名 | 保存内容と再読込が一致する |
| 古い版からの更新 | 新しい版を上書きせず再確認へ誘導 |
| 同時更新 | 1件だけ確定し、他方は競合。試験処理を排他制御 |
| 更新応答切断・再送 | 同じ更新結果を返し、履歴が二重にならない |
| 各領域への保存途中失敗 | 完了を表示しない。同じ認証・処理IDで再開できる |
| 途中応募への別更新 | 復旧待ちにし、処理中の候補を確定版として返さない |
| 締切境界 | 保存側の試験日時で検証。本番締切は勝手に設定しない |
| 締切後の既存結果確認 | 締切前に確定した結果の照会と、新規更新を区別 |
| 設定不足 | 本番の新規受付・更新を有効にしない |
| 認証情報の混入 | 履歴・共有表示・応答・通常ログにコードと検証値がない |
| 入力保持・編集終了 | 通信失敗時は入力を保持。終了時に画面のコードを破棄 |

実装後に自動テストと型チェック・ビルド、ブラウザでのPC／スマホ操作を検証する。失敗注入はローカルの模擬保存先に限定する。実コードの値や実応募データをテスト成果物・Gitへ保存しない。

## この検証では完了しない事項

Google実環境の共有権限・3ファイル書き込み・障害回復、本番通信・ログ・試行制限、正式受付番号、本番締切、運営相談の具体的手順、重複応募防止、公開準備。これらが残る間は、本番対応済みと案内しない。
