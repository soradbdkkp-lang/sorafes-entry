# Phase 5 Google実環境の架空データ試験計画（提案・未実施）

2026-10-09作成。目的は、ローカルで確認した重複応募チェックがGoogle Sheets / Apps Scriptの保存・編集・排他・再送と組み合わさっても成立するかを、架空データだけで検証すること。これは本番受付・本番保存先の決定ではない。Google側の作成・変更、試験APIの有効化・配備は、この計画への承認後に行う。

## 試験方式と残る判断

- 同一フォーム内では入力中に候補を表示し、Google上の既存応募とは保存時に保存側の排他中で照合する。2026-10-09に本番もこの時点の照合を採用した。既存応募への独立した検索APIは作らない。
- 照合範囲・ID比較・一方だけ一致した場合の保留と二種類の文言は [採用済みの判断](phase5-design-proposal.md) に従う。認証済みの自己応募を除外し、旧版や他大会は照合しない。
- 一方だけ一致した正当な別人の応募も、今回の試験では保存を保留する。相談先は [運営Xアカウント](https://x.com/sora_kkp_game)。運営による例外承認・本人確認の手順は未確定であり、試験用の例外処理は実装しない。
- 既存のPhase 4と同程度の試験用アクセス制限を仮置きして検証する。本番の照会回数・時間の上限、制限を設ける場所、公開通信方式は未決定のままにする。

## 作成・変更を提案する対象

| 対象 | 提案する作業 | 境界 |

| 新規スプレッドシート `sorafes-entry Phase5 認証試験` | 所有者だけが閲覧・編集できる非公開ファイルを作成 | 編集コード原文は保存せず、検証値・処理状態を保持。既存Phase 4認証ファイルを変更しない |
| 新規スプレッドシート `sorafes-entry Phase5 履歴試験` | 所有者だけの非公開ファイルを作成 | 変更前を含む架空応募の履歴を保持。運営メンバーへの追加共有は行わない |
| [指定応募スプレッドシート](https://docs.google.com/spreadsheets/d/1FU3cimJuHg5JGmJvVJpc-U0VNc4zTP5nB-DwiyW8VXE/edit)の新規タブ `sorafes-entry_PHASE5_TEST_v1` | 架空応募の最新確定版だけを表示する専用タブを追加 | ファイルの既存の「リンクを知っている全員：閲覧者」設定を継承。既存タブ・行・共有設定は変更しない |
| 新規の独立Apps Script `sorafes-entry Phase5 重複試験` | 初期停止で作成し、所有者が試験用Webアプリとして配備する案。実行者「自分」・アクセス「全員」を提案 | Phase 3・4のスクリプト、配備URL、停止設定を変更しない。配備時に設定と権限を所有者へ提示して確認する |
| このプロジェクト内のPhase 5専用ソース・模擬テスト・ローカル中継と試験画面 | 共通の入力検証・Phase 4の認証／版管理方式を利用し、Google保存時の重複判定を追加 | 試験キーはサーバー側だけに置き、ブラウザへ渡さない。既存依存だけを使い、既存 `.env.local` の設定を消さない |

新規保存先を分ける理由は、Phase 4に残る14件の架空応募がPhase 5の照合結果へ混入することと、停止済みPhase 4 APIや履歴を変更することを避けるため。Phase 5の受付番号には本番と区別できる試験用接頭辞を使い、正式フォーマットを決めた扱いにしない。タブ名やファイル名が既に存在する場合は上書きせず、確認して止める。

## Google側を変更する前の準備と確認

1. この計画の対象・共有範囲・配備範囲への承認を得る。接続アカウントが既存Apps Script所有者と同じことを再確認する。
2. プロジェクト内でPhase 5専用の保存コードと模擬試験を作る。既存Phase 4の生成コードや `.env.local` の秘密値は文書・Gitへ写さない。ローカルで型チェック、ビルド、全テストを実行する。
3. Google側の既存タブ・権限・Phase 3／4停止状態を読み取りで確認し、試験前の確認範囲を記録する。全使用範囲の不変を主張するなら、その範囲全体を前後で照合する。
4. 新規ファイル・専用タブ・独立スクリプトを初期停止で作成する。認証・履歴ファイルがリンク閲覧できないこと、共有応募タブに検証値が含まれないことを確認する。所有者の権限承認が必要なら所有者が操作する。

## 試験ケースと終了条件

1. 全5応募形式とチーム4／5／6名で架空応募を保存・認証読込・更新し、3保存先の受付番号・版・原本を照合する。
2. 同じフォーム内の重複、別応募とのX IDのみ・ゲーム内IDのみ・同じ相手に両方一致する場合を確認し、保留時は追加行・履歴・認証イベントが増えないことを照合する。公開応答には相手の受付番号、ID、内容、一致項目を含めない。
3. 認証済み自己編集、メンバー変更で外れた旧IDの解放、古い版の競合、同一処理IDの再送、処理途中の競合、同時送信で一方だけが確定することを検証する。
4. 不正な試験キー・編集コード、設定不足、期限切れ、停止状態を保存側で拒否する。応答切断はローカル中継で試し、Googleの既存権限を故障試験のために変更しない。
5. 試験後にPhase 5専用APIを停止し、停止後の設定取得・新規保存・更新の拒否、3保存先のデータ保持を確認する。架空データは削除しない。

模擬環境での同時送信・各書き込み失敗の検証は、Googleの実際の割当制限や長期運用性能を代替しない。試験結果では確認できた範囲と残る制限を分けて記録する。

## 承認範囲として提案するもの

上記の新規非公開2ファイル、指定応募ファイルへの専用1タブ、独立1スクリプトと試験配備、必要なプロジェクト内の実装、架空データだけの試験と試験後停止。既存行の上書き・移動・削除、Phase 3／4 APIの再開、既存ファイルの共有変更、履歴の追加共有、実応募データの使用、本番受付・公開、依存追加、Git add／commit／pushは含めない。

本番の正式締切は2026年10月24日23:59（日本時間）と決定済みだが、試験期限は別に設定する。初回大会のキラー一覧はVol.1参照の43体と決定済み。運営の誤判定・紛失時対応手順、履歴閲覧メンバー、本番保存・通信方式は、この技術試験の値から推定しない。
