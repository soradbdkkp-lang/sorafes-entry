# Phase 3 試験保存の設定手順

## 作成済みのものと残作業

保存契約・保存側の検証・試験保存画面・Apps Scriptコードを作成済み。所有者がGoogle上のプロジェクト作成・権限承認・配備を完了し、2026-10-07にローカル接続と架空データの実保存・再送・同時送信を確認した。本番受付は開始していない。

接続先は対象の試験Apps Scriptの「デプロイを管理」画面で確認する（実URLはGit管理外）。TEST_KEYはユーザー指定により既存値を使用し、値を文書・ソース・Git・共有シートに記録しない。

この構成はローカル開発時だけ使う試験用。ViteのローカルサーバーがApps Scriptに送信し、Googleのリダイレクトを追ってJSON応答を確認する。ブラウザから直接Googleへ送る方式や `no-cors` の不透明な応答を成功扱いする方式は使用しない。本番ホスティングの通信方式は別途未確定。静的ビルドや `npm run preview` では保存できない。

## Google側（所有者が設定）

1. [Apps Script](https://script.google.com/home)に、指定シートの所有者アカウントでログインする。
2. 新しい**独立した**プロジェクト「sorafes-entry 保存試験」を作る。既存プロジェクトへ追加しない。
3. `apps-script/generated/Code.gs` の内容を新規プロジェクトの `Code.gs` に貼り付けて保存する。コード更新後はローカルで `npm run build:apps-script` を実行して再生成する。生成処理は導入済みViteが利用するesbuildを使用し、依存を追加しない。
4. プロジェクトの設定 → スクリプトプロパティに `TEST_ENABLED` = `true` と、`TEST_KEY` = 自分で生成した十分長いランダムな試験用キーを登録する。キーはチャット・共有シート・Gitへ記録しない。
5. デプロイ → 新しいデプロイ → ウェブアプリ。実行ユーザーは「自分」、アクセスできるユーザーは「全員」にする。所有者のGoogle権限承認が必要。試験APIはキー一致・試験モード・大会ID・入力検証を満たす場合だけ保存する。シートの既存共有設定は変更しない。
6. 発行された `/exec` で終わるウェブアプリURLを控える。スプレッドシートのURLや `/dev` のURLでは接続できない。URLは秘密の認証情報ではないため、チャットで共有してよい。

## ローカル側

プロジェクト直下の `.env.local` に、以下の2項目を設定する。2026-10-07にユーザー指定の接続先とキーで新規作成済み。既存ファイルがある場合は他の設定を消さない。

```dotenv
SORAFES_APPS_SCRIPT_URL=https://script.google.com/macros/s/発行されたID/exec
SORAFES_TEST_KEY=Google側のTEST_KEYと同じ値
```

`.env.local` は既存 `.gitignore` の除外対象であり、作成後に `git check-ignore .env.local` で除外を確認済み。`.gitignore` は変更していない。秘密はViteのローカルサーバーだけで扱い、ブラウザに配信しない。開発サーバーを再起動して設定を読み込む。実行環境でGoogleへの通信が遮断されたため、許可を得て通信可能な開発サーバーを起動した。

## 試験と保存内容

架空の入力で確認画面まで進み、架空データ・永久保持・リンク閲覧の確認チェックを入れ、「架空データを試験保存」を押す。

保存先は指定シートの新規タブ `sorafes-entry_TEST_v1`。既存 `シート1` や共有設定は変更しない。専用タブ名が既に存在するときはヘッダー一致を検証し、不一致なら停止する。1応募につき1行で、試験保存ID・UTC保存日時・再送識別ID・大会ID・応募形式・人数・応募原本JSONを保存する。自由入力は `{` から始まるJSONに収め、セルの数式として解釈させない。認証キー、編集コード、抽選内部情報は保存しない。集計表・受付番号・編集認証は後続フェーズ。

同じ識別ID・同じ内容の再送は既存の保存IDを返す。異なる内容で同じIDを送ると停止する。試験保存IDは受付番号や編集権限ではない。同時処理はScriptLockで排他し、保存とflushの後に成功応答する。結果不明時は入力変更を抑止し、同じ識別IDで再確認する。再読み込みで識別ID・入力は消えるため、結果不明時は画面を閉じない。長期復旧・大量件数の性能・本番制限は未対応。

試験用の技術上限はリクエスト24,000文字。正式な名前・ID長や大会実績件数の業務条件を確定するものではない。正式締切未定のため本番期間判定は実装せず、試験の受付可否は `TEST_ENABLED` で制御する。試験終了後は `TEST_ENABLED` を `false` にして試験保存を止める。保存した情報は削除しない。

## 検証状況

- 2026-10-07：指定シートの名称、タブ `シート1`（ID 0、1,000行×26列）、先頭20行の空欄、リンク閲覧権限と所有者権限を読み取り確認。全1,000行が空欄かは未確認。
- 生成したApps Scriptを模擬Google環境で実行し、正常保存、対象外情報・キー除外、数式対策、再送、競合、入力改ざん、書き込み例外、保存後の結果不明、排他取得失敗を検証。Google実環境の試験を代替するものではない。
- 開発サーバー再起動後、ブラウザで架空入力・確認チェック・試験保存操作を行い、設定未完了の案内と入力保持を確認。外部送信・保存は発生していない。
- 実環境：ローカル送信経由の保存成功・JSON応答取得、同じ内容の再送で同じ保存ID、内容違いの同一IDをCONFLICTで拒否、不正人数をINVALIDで拒否、同じIDの同時2送信で1件だけ保存を確認。
- ブラウザ：架空入力から確認・試験保存・成功表示・成功後の保存ボタン無効を確認。表示された保存IDとシートの保存IDが一致。
- 保存先：`sorafes-entry_TEST_v1`（タブID 1159489116）の2〜4行に架空の試験データ3件を確認。既存 `シート1` の先頭20行は空欄のまま。保存データは削除していない。共有設定を変更していない。
- 再開後：全応募形式とチーム4 / 5 / 6名の計7パターンを実保存し、シートの期待値一致・再送時の行数不変を確認。保存後の応答をローカルで切断する試験では、画面の結果不明・入力保持・再確認成功と二重保存防止を確認した。誤ったキーはGoogle側でDENIEDを確認。架空データ8件を追加し、計11件を保持。詳細は `phase3-verification.md`。
- 2026-10-08：所有者の受付停止設定後、有効な架空応募がCLOSEDで拒否され、専用タブの前後のセル内容が不変・11件保持であることを確認。試験APIは停止中。
- 未検証：Google実環境での保存先権限拒否・内部書き込み途中の故障、大量送信と利用制限。本番用の通信・運用、再読み込み後の結果復旧、受付番号・編集認証は未対応。Phase 3の全受け入れ条件を完了したとは扱わない。
