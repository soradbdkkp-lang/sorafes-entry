# Phase 4 ローカル実装・検証結果

2026-10-08。ユーザーの明示承認により、架空データを使ったローカル実装・検証を実施した。Google側のファイル・スクリプト・共有設定・停止設定は変更していない。

## 確認方法

導入済み環境で `npm run dev` を使用し、`http://127.0.0.1:5173/?phase4` を開く（ポートは起動表示に従う）。通常フォームのGoogle試験保存とは別入口。静的ビルドや `npm run preview` にはローカル保存APIがない。

新規試験用コードを生成し、保存票をダウンロードするかコードと再確認IDを手元に控える。架空データ・保存確認をチェックして既存フォームへ入力し、確認画面でローカルへ試験応募する。成功後は受付番号とコードで応募を読み込み、更新用の再確認IDを保存して修正する。

結果不明のときは、失敗試験を「正常」へ戻して同じ操作を再確認する。ページを再読み込みした場合も、保存票の再確認IDとコードから保存済み・途中処理を再確認できる。準備保存より前に失敗した処理は保存記録がなく、この方法では復旧できない。

## 実装の境界

- Vite開発サーバー内のメモリで認証・履歴・共有表示の3領域を模擬。Googleへは通信しない。サーバー再起動で試験データは消える。永続保存・実共有権限の検証ではない。
- ブラウザで16バイトの暗号学的乱数を生成し、表示は32桁の16進数を区切る。コードは自動永続保存せず、終了時に画面から破棄する。
- 保存側はSHA-256検証値を保持し、コード原文を保持しない。受付番号は仮の `LOCAL-` 連番で本番形式ではない。
- 保存側で既存の応募条件を再検証。応募形式・人数変更でも同じ受付番号を維持する。原本・改訂版は履歴領域へ保持し、共有表示は最新内容を模擬する。
- 操作を直列化し、期待版・処理ID・状態管理で競合と再送を処理。認証後の同じ処理だけを途中から回復する。
- 試験締切は模擬保存先初期化から24時間。日本時間で表示する。正式締切は設定していない。期限判定は保存側で行い、準備済み処理の復旧と新規受付・更新を区別する。
- 試行制限は仮に番号ごと5回失敗／60秒、全体200操作／60秒。正式運用値ではなく、本番の送信元制限・過負荷対策を代替しない。
- 失敗注入はローカル専用。準備保存前・履歴保存前・共有表示反映前・確定記録前・成功応答切断を選べる。

## 実施した検証

`npm test`：26件成功（既存17件＋Phase 4追加9件）。型チェック・Viteビルド成功。

追加テストで全5形式・チーム4／5／6名の保存と認証読込、形式変更、原本保持、認証失敗と非開示、同一再送、内容違いの拒否、古い版と同時更新、各段階の途中失敗と回復、処理中の旧確定版読込、締切境界・未設定拒否、不正入力・対象外項目除外、コード／検証値の混入防止、短時間制限の時間経過での解除を確認した。

ブラウザで架空の1人応募を入力し、成功後の応答切断を再現。結果不明時に修正へ進めず、同じ操作の再確認で版1を受領できた。その後認証して名前を修正し、確定記録前に失敗させ、再読み込み後にIDとコードで復旧して版2を確認。再認証で修正後の内容を確認した。終了操作で画面内のコードを消去した。

スマートフォン設定390×844で本文幅とスクロール幅が375pxで一致し、横はみ出しがないことを確認した。PC表示も確認。保存票ダウンロード操作そのものと、コピー・ファイル保存後の再入力は未検証（ブラウザ試験ではコードとIDを試験セッション内に保持して再入力した）。
