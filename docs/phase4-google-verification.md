# Phase 4 Google実環境の検証記録

試験実施：2026-10-08。停止状態と保存データの再確認：2026-10-09。対象は架空データ専用の独立した試験構成であり、正式な応募受付ではない。保存先と配備のリンクは [phase4-google-setup.md](phase4-google-setup.md) に記す。

## 確認した動作

| 項目 | 結果 |
| --- | --- |
| 全5応募形式・チーム4／5／6名 | 各形式・人数で新規保存、認証読込、版2への編集、処理IDとコードによる再確認に成功。チーム6名は通信の結果不明後に別の架空応募で再検証した |
| 再送・競合 | 同一処理ID・同一内容の再送は同じ結果。古い版からの更新は `CONFLICT`。同じ版からの並行2更新は1件だけ成功し、もう1件は競合した |
| 誤認証・故障指定 | 誤った編集コードは `DENIED`。外部APIへの故障注入指定は `INVALID` |
| 画面 | `/?phase4=google` から架空のソロ応募を保存し、受付番号を表示。認証読込、プレイヤー名の編集、再読み込み後に保存した処理ID・コードから版2の結果を再確認した |
| 自動検証 | 既存テストを含む33件が成功。Apps Script模擬環境では各保存段階の直前・直後・flush失敗からの再送を検証した |

Googleから応答が遅れたり、JSONでない応答が返ったりした。成功と推測して新しい処理IDで再送せず、同じ処理ID・同じ入力で確認した。初回のチーム4名試験の版1、通信結果を取得できなかったチーム6名試験の版1は、架空データとして残っている。後者の編集コードは初回試験処理の終了後に保持されておらず、その行について後追いの認証編集はしていない。別の架空6名応募で保存・読込・編集・回復を確認した。これらの試験データは削除しない。

## 保存先と権限

2026-10-08の最終照合、および2026-10-09の再確認で、公開応募タブに14応募、非公開履歴に28行、非公開認証管理に56イベントを確認した。公開応募タブの14行はすべて `committed`。各公開行の版・応募原本は同じ受付番号・版の履歴、および認証管理の最新確定状態と一致した。履歴の受付番号・版の組に重複はなかった。共有応募タブと履歴ファイルに認証検証値が含まれないことを確認した。編集コード原文も保存側の設計・模擬テストでは残らないが、実環境の全セルから原文を照合する検査はしていない。

認証・履歴ファイルはそれぞれGoogle Driveの権限表示で所有者1名のみ、`shared=false` を確認した。指定応募ファイルは従来どおり「リンクを知っている全員：閲覧者」。既存 `シート1!A1:Z20` と `sorafes-entry_TEST_v1!A1:G25` は専用タブ追加の前後でセル値が一致した。既存タブの全使用範囲は照合していない。

## 試験後の停止

新規Phase 4スクリプトの `PHASE4_ENABLED` を `false` に戻した。2026-10-09に設定画面で `false` を読み取り、同じ配備URLへの設定取得・新規保存・更新がそれぞれ `CLOSED` を返すことを確認した。上記14応募・28履歴・56認証イベントも保持されていた。旧Phase 3スクリプトと停止設定、既存応募ファイルの共有設定は変更していない。
