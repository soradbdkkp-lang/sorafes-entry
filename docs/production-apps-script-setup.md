## 配置物

`npm run build:production` で以下を生成する。生成はローカルだけで行い、Googleへ自動配備しない。

| ファイル | Apps Script側の名前 | 内容 |
| --- | --- | --- |
| `apps-script/production-generated/Code.gs` | `Code.gs` | 保存、認証、更新、重複判定、HTML配信 |
| `apps-script/production-generated/Index.html` | `Index.html` | React画面・CSS・同一Webアプリ通信をまとめた単一HTML |
| `apps-script/production-generated/appsscript.json` | `appsscript.json` | 日本時間、V8、スプレッドシート権限だけを明示する候補 |

このHTMLは運営の保存経路検証画面として残し、`google.script.run` で同じApps Scriptプロジェクトの `handleProduction` を呼ぶ。正式応募画面には使用しない。参加者向け本番画面はCloudflare Workersから配信し、同一オリジン `/api/entry` の中継を通して本Webアプリの `doPost()` を呼ぶ。Cloudflare構成は [cloudflare-deployment.md](cloudflare-deployment.md) を参照する。

## 新規作成するGoogle側の対象

既存のPhase 3・4試験ファイル、試験Apps Script、停止設定は変更しない。本番用に次を新規作成する。

| 対象 | 初期共有範囲 | 必須タブと1行目 |
| --- | --- | --- |
| 本番認証スプレッドシート | Apps Script所有者のみ | `認証管理`：`記録日時UTC`, `処理状態`, `受付番号`, `認証管理JSON`, `操作JSON` |
| 本番履歴スプレッドシート | 運営アカウント限定。当面は所有者のみ | `応募履歴`：`受付番号`, `版`, `処理ID`, `保存日時UTC`, `応募原本JSON` |
| 本番応募一覧を置くスプレッドシート | 運営アカウント限定。当面は所有者のみ | `応募一覧`：`受付番号`, `版`, `処理ID`, `処理状態`, `保存日時UTC`, `応募原本JSON` |
| 本番Apps Script | 所有者のみ編集 | 上記3生成ファイルを配置。新しい独立プロジェクト |

本番用の3スプレッドシートと独立Apps Scriptは作成済み。認証・履歴・応募一覧は所有者限定であり、追加する運営アカウントが決まるまで共有相手を増やさない。Apps Script生成ファイルと設定値を反映し、実行者を所有者、アクセスを全員としてWebアプリを配備済み。`FAC-2026-` の設定検査修正後にバージョン2へ更新し、架空データの新規保存・再確認・重複拒否・認証失敗を確認した。検証後は受付停止へ戻した。詳細は [本番保存経路のGoogle実環境検証](production-google-verification.md) を参照する。

## 採用した本番設定

早期公開、試験環境からの分離、応募情報の限定共有を優先し、次を採用した。

| 項目 | 推奨値 |
| --- | --- |
| 受付番号接頭辞 | `FAC-2026-`。続けて6桁の連番を付ける |
| 本番応募一覧 | 新規ファイル `sorafes-entry 本番応募一覧`、タブ `応募一覧` |
| 応募一覧の権限 | 運営アカウント限定。当面は所有者のみが閲覧・編集 |
| 応募一覧URLの配布 | フォームに掲載せず、追加する運営アカウント確定後に限定共有 |
| 本番履歴の権限 | 初回公開時は所有者のみ。具体的な運営メンバー確定後に個別共有 |
| 本番認証の権限 | 所有者のみ |
| Webアプリ | 実行者は所有者、アクセスは全員、初期状態は受付停止 |
| 全体の短時間制限 | 1分あたり200要求。超過時は一時的に再試行を案内 |
| 認証失敗制限 | 同じ受付番号で1分あたり5回。超過時は一時的に拒否 |

恒久的なアカウントロックや編集コードの自動再発行は行わない。

## スクリプトプロパティ

配備前は必ず `PRODUCTION_ENABLED=false` とする。

| キー | 値 |
| --- | --- |
| `PRODUCTION_ENABLED` | 初期値 `false` |
| `PRODUCTION_NEXT` | 最後に消費した番号。現在は文字列 `4`。次番号そのものではない。巻戻し・欠番再利用禁止 |
| `PRODUCTION_TRAFFIC` | 自動管理される直近60秒の要求時刻配列。通常は手動設定・削除不要 |
| `PRODUCTION_AUTH_ID` | 新規の本番認証ファイルID |
| `PRODUCTION_HISTORY_ID` | 新規の本番履歴ファイルID |
| `PRODUCTION_PUBLIC_ID` | 本番応募一覧を置くファイルID |
| `PRODUCTION_PUBLIC_SHEET` | 決定した応募一覧タブ名 |
| `PRODUCTION_RECEIPT_PREFIX` | 決定した受付番号接頭辞 |
| `PRODUCTION_DEADLINE_UTC` | `2026-10-24T14:59:00.000Z` |

3つのファイルIDは別々でなければならない。接頭辞は大文字英数字と末尾ハイフン、20文字以内。設定不足、期限不一致、受付停止の場合は保存処理を閉じる。

完全新規で既存記録・消費番号がない初回だけNEXT=0。既存環境の再配備・再開では現在値を維持する。採番後・prepared前の失敗でも番号を戻さない。復旧時は現在値、応募一覧・履歴の最大番号、preparedを含む認証記録、既知の消費記録を照合し、それ未満へ戻さない。不明なら停止維持・調査とし、値変更は別途承認する。シート最大値だけを根拠に下げない。設定画面の保存前に最新プロパティを再読み込みし、古いNEXTを一括保存しない。詳細は [採番運用](production-operations.md#採番)。

## 配備と確認順序

1. 確定した設定で、本番用の3保存先と独立Apps Scriptを作る（完了）。
2. 生成した3ファイルを配置し、スクリプトプロパティを設定する。受付は停止したままにする。
3. Webアプリは実行者を所有者、アクセスを全員として新規配備する。公開URLを取得しても、この時点では受付を開始しない。
4. 停止中の公開URLが画面を表示し、保存・読込・更新を拒否することを確認する。
5. 対象・時間・停止条件を個別承認した架空データ試験だけ、一時有効化して実施する。全形式・人数・更新等の元の検証項目は、実施済み／未検証／受容判断を区別する。今回の追加試験は新規2件＋recover1件であり、全項目合格ではない。
6. 3保存先、共有範囲、秘密情報の非混入を照合して再び停止する。架空データは実応募と区別できる状態を維持する。
7. 公開URLと注意事項を運営が確認し、実応募受付開始の最終操作として `PRODUCTION_ENABLED=true` にする。

Googleの権限承認、全員アクセスの配備、共有設定、受付有効化は外部状態を変更する。対象・権限・設定値を提示したうえで実行直前に確認する。

## ローカル確認済みの範囲

- 本番モードと大会IDの付与、試験用フラグを送らないこと。
- Apps Script失敗、不正応答、実行環境外を成功扱いしないこと。
- HTML Serviceの `Index.html` 配信とビューポート設定。
- Cloudflare本番サイト用クライアントが同一オリジン `/api/entry` だけを呼び、Apps Script URLをブラウザへ出さないこと。
- Workerが本番契約を付与し、受付停止・重複・認証失敗を保ち、不正応答を結果不明にすること。
- 受付番号・編集コード、認証読込、更新、版競合、再送・途中失敗回復。
- 同じフォーム内と最新確定応募との重複判定、認証済み自己編集の除外。
- 編集コード原文と検証値を本番応募一覧・履歴・応答へ含めないこと。

Google実環境で本番3ファイルが所有者限定であること、架空データの新規保存、同一処理再確認、重複拒否、誤コード拒否、試験後の受付停止を前工程で確認済み。2026-10-12にはCloudflare本番画面からteam6・killerの保存と確定済みrecover成功、3保存先照合、停止表示を確認した。正式URLの公開案内、スマートフォン実機、Googleの長期的な割当制限、残る応募形式・人数・更新・途中失敗の本番経路は今回未検証。詳細は [追加試験記録](production-additional-verification.md)。
