# Phase 5：重複応募チェックの採用判断と設計提案

2026-10-09作成。Phase 4の架空データ試験は終了し、Google試験APIは停止中。ユーザーは同日、照合範囲、ID比較、一方だけ一致した場合の保留と表示文言の区別について下記の案を採用した。これを基に架空データ専用のローカル試作を実装・検証した。本番運用の細部、Google側のPhase 5実装、本番受付開始は未承認。試験データや既存のGoogle設定は変更していない。

## 確定済みの要件と境界

- 同一フォーム内と既存応募のX ID・ゲーム内IDを重複候補として確認する。名前だけの一致では同一人物と断定しない。
- 重複時の案内は「このプレイヤーはすでにエントリーされています。」を基本とし、入力の確認・修正と既存応募の編集へ誘導する。編集には受付番号・編集コードの認証が必要。重複照合を編集権限として使わない。
- 認証前に他の応募内容、受付番号、所属チーム、照合したIDや一致理由をフォームAPIから返さない。応募シートのリンク閲覧方針と、フォームAPIの情報公開範囲は別に扱う。
- 個人情報の追加取得、実応募データを使った試験、試験APIの再開、本番受付はこの提案の範囲外。Phase 3・4の架空試験行を正式応募として数えない。

## 採用した判断

| 判断項目 | 採用内容 | 理由・影響 |
| --- | --- | --- |
| 照合範囲 | 同じ大会の最新**確定**応募に含まれる全プレイヤー。編集時は認証済みの自分の受付番号を除外する。履歴は対象にしない | 別大会・旧版・変更で外れたメンバーによる誤警告を避ける |
| IDの比較 | X IDは前後空白・先頭`@`を除き、英字の大小をそろえる。ゲーム内IDは前後空白だけ除き、`#`以降と文字の大小を保つ。表示・保存する原文は比較用文字列で上書きしない | 既存の入力整形と整合させつつ、ゲーム内IDの未確認な同一視を避ける |
| 1項目だけの一致 | X IDかゲーム内IDの一方だけが一致しても「重複候補」として保存を保留する。自動で同一人物と断定しない | 見逃しを抑える一方、正当な応募も止まる場合がある。本人でないときの運営対応は未確定 |
| 表示文言 | 一方だけ一致した場合は「重複の可能性があります。入力内容を確認してください」。同じ相手に両方一致した場合は「このプレイヤーはすでにエントリーされています。」。どちらも保存は保留 | 一方だけの一致を確定した同一人物と断定しない |
| 照合の時点 | フォーム内は入力中に表示し、既存応募は保存時に保存側の排他中で照合・確定する。入力中に外部照会しない | 早期公開を優先し、外部照会の通信・照会制限の複雑化を避ける。保存時の最終チェックはどちらの方式でも必要 |

処理途中の候補は確定応募と断定せず、復旧または競合解消まで重なる別処理を保留する。この具体的な整合処理はローカル試作で検証した。

## 追加の提案（未決定）

| 判断項目 | 提案 | 理由・影響 |
| --- | --- | --- |
| 応答と照会制限 | 外部照合は一般的な候補結果だけ返し、他応募の内容や一致項目を返さない。認証失敗・照会の回数制限と全体の過負荷対策を設ける | IDを変えながら照会する行為を抑える。具体的な回数、時間、実装場所は本番通信方式と合わせて決める |

フォーム内では、どの**入力欄同士**が重なったかを本人に示せる。既存応募との照合では、入力した側のプレイヤー番号だけを示し、相手の情報は表示しない。二つのIDがともに一致する場合も、公開応答の詳細度は増やさない。

フォーム内ではどちらの一致でも、自分が入力した欄同士の確認を促す。上記の二種類の文言は既存応募との照合結果に用いる。ローカル試作では相手の受付番号・ID・一致項目を返さず、二段階の一般的な結果だけ返す。

## 保存・編集との接続案

1. 現在の応募形式・人数で有効なプレイヤーだけを対象に、既存の入力検証と同じ整形後データから比較用IDを作る。一時保持されている対象外メンバーは照合しない。
2. フォーム内の重複候補を本人に示し、確認・修正できるようにする。既存応募への照会は一覧取得APIにしない。
3. 新規保存・認証済み編集では、既存の処理IDによる再送と版競合の判定を維持する。同じ操作の再確認は新規の重複応募として扱わない。
4. 保存側の排他中に最新確定応募を照合する。編集中の自分の応募は受付番号で除外し、他応募との一致があれば確定しない。重なる処理途中の候補があれば、復旧または競合解消まで後続処理を保留する。照合と確定の間に別の保存が入らないことを検証する。
5. 処理途中で通信が切れた場合はPhase 4の再確認・回復導線へ戻し、結果不明のまま別の処理IDで再送しない。過去の版と試験データは削除しない。

## 残るユーザー判断

1. 一方だけ一致して本人でないときは [運営Xアカウント](https://x.com/sora_kkp_game)を相談先として案内する。本人確認・判断手順、例外を認める条件や実装方式は未決定。
2. 既存応募の照会回数・時間の上限と、制限をかける場所。本番通信方式が未確定のため、試験用Apps Scriptの設定を本番値とみなさない。
3. 本番保存先・通信方式等の公開前条件。ローカル試作の設定を本番値とみなさない。

## 決定後の段階的な検証案

既存依存だけで架空データのローカル保存先を使う最初の試作を実施した。比較・フォーム内・別応募・認証済み自己編集・版更新・同時保存・処理途中の保留を確認した。結果と未検証項目は [phase5-local-verification.md](phase5-local-verification.md)。Google実環境の架空データ試験は [対象・権限・停止方法の計画](phase5-google-test-plan.md) を提案中。Google側の作成・変更や試験API再開は、この計画への承認後に行う。
