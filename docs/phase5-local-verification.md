# Phase 5 ローカル重複チェックの検証記録

実施日：2026-10-09。`/?phase5` は架空データ専用のローカル試験画面。保存先は開発サーバーのメモリであり、Googleには接続しない。Phase 4のローカル保存先とも分離した。試験APIの再開、本番受付、依存追加は行っていない。

## 実装した範囲

- 比較用のX IDは前後空白・先頭`@`・英字大小をそろえ、ゲーム内IDは前後空白だけを除く。原文は変更しない。
- 現在の応募人数に含まれるプレイヤー同士は入力画面で重複候補を表示し、保存を止める。対象外の一時保持メンバーは照合しない。
- ローカル保存時は、同じ大会の他の最新確定応募に含まれるプレイヤーを照合する。一方のIDだけの一致でも保留する。認証済み編集では自分の応募を除外する。
- 別応募の処理途中の候補と重なれば、その処理が確定・復旧するまで保留する。同時送信は既存の順序制御下で照合する。同じ操作の再送は新規の重複として扱わない。
- 既存応募との照合結果には、相手の受付番号・内容・一致した項目を含めない。一方だけ一致した候補と、同じ相手に両方一致した場合の二種類の文言を区別する。フォーム内の重複では本人が入力したプレイヤー番号と一致項目だけ示す。

## 検証結果

| 方法 | 結果 |
| --- | --- |
| Node自動テスト | 既存33件とPhase 5の6件、計39件成功。比較方法、有効人数、一方だけの一致、自己編集、旧IDの解放、処理途中、同時送信、再送に加え、全5応募形式とチーム4／5／6名の最後の有効メンバーまで保存側で照合することを確認 |
| 型チェック | `tsc --noEmit` 成功 |
| Viteビルド | `vite build --outDir dist/phase5-build` 成功。出力はGit除外の`dist`内 |
| ブラウザ | `/?phase5` を開き、2人応募のX IDを`@ExampleUser`と`exampleuser`にするとプレイヤー1・2の重複候補が表示された |
| 画面からの保存 | 架空の1人応募をローカルで版1として保存。同じ二つのIDで再応募すると「このプレイヤーはすでにエントリーされています。」、ゲーム内IDだけ変更してX IDのみ一致させると「重複の可能性があります。入力内容を確認してください」と表示され、どちらも保存を保留した |
| 画面からの認証済み編集・回復 | 別タブの架空1人応募を保存し、受付番号と編集コードで読み込んだ。プレイヤー名を修正して確認画面へ戻り、更新時の応答切断後に同じ操作を再確認すると、同じ受付番号の版2を受領した。再確認IDは読込後に更新用へ切り替わった |
| スマートフォン幅 | 390pxのビューポート指定で確認画面と版2の結果表示を確認し、ページ全体に横はみ出しがないことを確認した |

ブラウザ操作で使用した値は架空で、サーバー再起動時に消える。一方だけ一致した場合と両方一致した場合の基本文言は採用済み。本人でない場合の相談導線は未確定。
