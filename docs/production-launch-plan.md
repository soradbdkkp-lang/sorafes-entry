## 現在地

- 正式な応募・編集締切は2026年10月24日23:59（日本時間）。保存側では `2026-10-24T14:59:00.000Z` と一致しない設定を拒否する。
- 本番候補の保存処理を `apps-script/production-server.ts` に分離した。Phase 3・4の試験スクリプトや停止設定は変更しない。
- 本番モード・大会ID・3保存先・応募一覧タブ名・受付番号接頭辞・正式締切がすべて設定され、さらに `PRODUCTION_ENABLED=true` の場合だけ処理する。欠落・不一致時は `CONFIG` または `CLOSED` として受付を閉じる。
- 受付番号・編集コード、認証読込、全項目編集、版競合、同一処理の再送、途中失敗回復、最新確定応募との重複照合を本番候補へ統合した。

- Apps Script HTML Service用の単一画面と同一Webアプリ通信を実装・配備し、本番保存経路の架空データ試験に使用した。この検証画面は運営用として残す。
- 正式公開はCloudflare WorkersからReact + Viteの画面と同一オリジン `/api/entry` を提供し、WorkerがApps Script `doPost()` へ転送する。ローカル実装、自動テスト、本番ビルド、Wrangler dry-runとSecret未設定時の安全な拒否を確認済み。

## 正式公開で必要な構成

参加者は `sorafes-entry` の本番サイト上で入力・確認・送信・完了まで行い、Apps Scriptは裏側の保存処理として使用する。通常の応募フローでGoogle Apps Scriptの案内バーを表示しない。公開先はCloudflare Workers、通信は同一オリジン `/api/entry` を採用した。保存失敗を成功扱いせず、正常な確定応答時だけ `FAC-2026-...` を表示する。詳細は [Cloudflare本番サイト構成](cloudflare-deployment.md) を参照する。

## 本番候補のGoogle構成

以下のGoogle側対象は作成済みで、当面の共有範囲を維持している。

| 対象 | 用途・権限 |
| --- | --- |
| 本番認証ファイル | Apps Script所有者だけが閲覧・編集。編集コード原文ではなく検証値、受付番号対応、処理状態を保持 |
| 本番履歴ファイル | 運営アカウント限定。当面は所有者のみ。修正前を含む応募原本を削除せず保持 |
| 本番応募一覧タブ | 最新確定版を保持。運営アカウント限定で、当面は所有者のみ閲覧・編集可能。フォームにURLを掲載しない |
| 本番Apps Script | 上記3保存先を更新し、受付・編集・重複判定を行う。試験プロジェクトとは分離 |

必要なスクリプトプロパティは以下。実値やファイルIDを文書・Gitへ記録しない。

| 設定 | 条件 |
| --- | --- |
| `PRODUCTION_ENABLED` | 初期値 `false`。全検証完了後の受付開始操作でだけ `true` にする |
| `PRODUCTION_AUTH_ID` | 本番認証ファイルID |
| `PRODUCTION_HISTORY_ID` | 本番履歴ファイルID |
| `PRODUCTION_PUBLIC_ID` | 本番応募一覧を置くファイルID |
| `PRODUCTION_PUBLIC_SHEET` | 本番応募一覧タブ名 |
| `PRODUCTION_RECEIPT_PREFIX` | `FAC-2026-` |
| `PRODUCTION_DEADLINE_UTC` | `2026-10-24T14:59:00.000Z` |

## 公開前の検証順序

1. 受付番号接頭辞、本番応募一覧の保存先・タブ名、初期共有範囲を確認する（決定・作成済み）。
2. Apps Script用のフォームと保存処理の生成物にファイルID・編集コード・秘密値が入らないことを確認する。
3. Google側の本番認証・履歴・応募一覧の3ファイルと独立Apps Scriptは作成済み。既存試験行・試験スクリプト・停止設定を変更せず、公開前に本番の受付停止と所有者限定権限を再確認する。
4. 架空データだけで全5応募形式とチーム4／5／6名の保存・読込・更新・重複保留・再送・応答切断回復を確認する。
5. 認証情報が応募一覧や履歴へ混入しないこと、非公開2ファイルの共有範囲、応募一覧の閲覧・編集範囲、正式締切後の拒否を確認する。
6. 公開URL、応募者向け注意事項、障害時の受付停止手順を運営が確認する。
7. `PRODUCTION_ENABLED=true` にして受付開始日時を記録する。公開後に架空データを本番応募へ混ぜない。

## 応募者へ表示する情報取扱い

公開前プレビューでは、応募情報を運営限定の保存先へ残し、そらふぇすが運営する大会でのみ使用すること、修正前情報を含め大会後も削除しないこと、編集コードを本番応募一覧や履歴へ保存しないことを送信前に示す。フォームで求めていないDiscord ID、メールアドレス、電話番号、本名、住所等は入力しないよう案内する。
