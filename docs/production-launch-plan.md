## 本番候補のGoogle構成

以下のGoogle側対象は作成済みで、当面の共有範囲を維持している。

| 対象 | 用途・権限 |
| --- | --- |
| 本番認証ファイル | Apps Script所有者だけが閲覧・編集。編集コード原文ではなく検証値、受付番号対応、処理状態を保持 |
| 本番履歴ファイル | 運営アカウント限定。当面は所有者のみ。修正前を含む応募原本を削除せず保持 |
| 本番応募一覧タブ | 最新確定版を保持。運営アカウント限定で、当面は所有者のみ閲覧・編集可能。フォームにURLを掲載しない |
| 本番Apps Script | 上記3保存先を更新し、受付・編集・重複判定を行う。試験プロジェクトとは分離 |

必要なスクリプトプロパティは以下。実値やファイルIDを文書・Gitへ記録しない。

| 設定 | 条件 |
| --- | --- |
| `PRODUCTION_ENABLED` | 通常の準備中は `false`。個別承認された限定試験または正式開始操作でだけ `true` にし、限定試験後は直ちにfalseへ戻す |
| `PRODUCTION_NEXT` | 最後に消費した番号。現在 `4`。非巻戻し・欠番非再利用。初回設定・復旧照合は本番運用ルールに従う |
| `PRODUCTION_TRAFFIC` | 自動管理の直近60秒の要求時刻配列。通常は手動初期化不要 |
| `PRODUCTION_AUTH_ID` | 本番認証ファイルID |
| `PRODUCTION_HISTORY_ID` | 本番履歴ファイルID |
| `PRODUCTION_PUBLIC_ID` | 本番応募一覧を置くファイルID |
| `PRODUCTION_PUBLIC_SHEET` | 本番応募一覧タブ名 |
| `PRODUCTION_RECEIPT_PREFIX` | `FAC-2026-` |
| `PRODUCTION_DEADLINE_UTC` | `2026-10-24T14:59:00.000Z` |

## 公開前の検証順序

1. 受付番号接頭辞、本番応募一覧の保存先・タブ名、初期共有範囲を確認する（決定・作成済み）。
2. Apps Script用のフォームと保存処理の生成物にファイルID・編集コード・秘密値が入らないことを確認する。
3. Google側の本番認証・履歴・応募一覧の3ファイルと独立Apps Scriptは作成済み。既存試験行・試験スクリプト・停止設定を変更せず、公開前に本番の受付停止と所有者限定権限を再確認する。
4. 元の検証項目（全5形式・チーム4／5／6名・読込・更新・重複・再送・応答切断回復）の実施済みと未検証を区別する。追加試験は個別承認されたケースだけに限定し、残る未検証範囲は開始前に受容判断を明示する。今回の試験で全項目確認済みとはしない。
5. 認証情報が応募一覧や履歴へ混入しないこと、非公開2ファイルの共有範囲、応募一覧の閲覧・編集範囲、正式締切後の拒否を確認する。
6. 公開URL、応募者向け注意事項、障害時の受付停止手順を運営が確認する。
7. [開始前チェック](production-operations.md#正式受付開始前チェック)を確認し、別途正式開始の明示承認後だけ `PRODUCTION_ENABLED=true` にして開始日時を記録する。試験4件は保持したまま、集計・抽選・当選・連絡・CSV等から明示ID集合で除外する。NEXTを戻さない。
