# 本番保存経路のGoogle実環境検証

2026-10-11、本番用に分離した3保存先とApps Scriptを使い、実在人物と結び付かない架空データだけで保存経路を検証した。本検証は正式な応募受付ではない。検証後は `PRODUCTION_ENABLED=false` へ戻し、公開URLに「現在、応募受付は停止しています。」と表示されることを確認した。

実際のファイルID、編集コード、編集コード検証値は本書・Gitへ記録しない。

## 修正と再配備

- 確定済みの受付番号接頭辞 `FAC-2026-` を設定検査が受理するよう、接頭辞を「大文字英数字の1区間」ではなく「ハイフンで区切られた大文字英数字の1区間以上、末尾ハイフン必須」として検査するよう修正した。
- `FAC-2026-` の受理と、二重ハイフン・先頭ハイフン・小文字・空白・末尾ハイフン欠落の拒否を自動テストへ追加した。
- ローカルの自動テスト49件と本番用生成に成功した後、既存Webアプリをバージョン2へ更新した。デプロイURLは変更していない。

## 保存された項目

本番応募一覧には、受付番号、版、処理ID、処理状態、保存日時UTC、応募原本JSONを1行保存した。応募原本JSONには応募形式、人数、チーム名、代表者番号、参加可能時間と、各プレイヤーのプレイヤー名、X ID、プレイ環境、その他環境、ゲーム内ID、総プレイ時間、キラー担当可否・担当区分・使用可能キラー・最得意キラー、DIF・DCK・その他大会の回答と詳細を格納する。今回の架空応募では該当しない詳細を空値または空配列として保存した。

本番履歴には、受付番号、版、処理ID、保存日時UTC、同じ応募原本JSONを1行保存した。本番認証には、準備と確定の2記録として記録日時UTC、処理状態、受付番号、認証管理JSON、操作JSONを保存した。編集コード原文はどのスプレッドシートにも保存せず、認証管理には検証値だけを保存した。

保存試験後の行数は、本番応募一覧1件、本番履歴1件、本番認証2件（準備・確定）だった。重複送信と認証失敗による追加行はない。

## 試験データの扱い

応募情報を削除しない確定方針に従い、試験行は削除していない。プレイヤー名、X ID、ゲーム内IDで架空試験データと明確に識別できる状態を維持する。正式受付開始後の集計では、この受付番号と架空識別値を試験データとして除外する。
