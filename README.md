# sorafes-entry

そらふぇす配下の大会で再利用する共通エントリーシステム。大会設定を差し替え、ふろぐCup、派生大会、特殊ルール大会にも対応することを目標とします。

初回対象は **ふろぐ Assemble Cup（2026年11月14日開催）** です。大会固有の名称・日程・質問条件を共通フォームの処理に密結合させません。

Phase 2の5応募形式、人数別入力、条件付き表示、入力チェック・確認・修正導線を実装済みです。Phase 4は架空データ専用のローカル受付・編集・失敗回復を実装し、自動テストとブラウザで検証しました。[確認方法・検証結果](docs/phase4-local-verification.md)を参照してください。本番候補には受付・編集・重複照合を統合済みです。本番用Google保存先とApps Scriptは所有者限定で作成し、`FAC-2026-` 修正後の架空データ保存・再確認・重複拒否・認証失敗を実環境で確認しました。検証後は受付停止へ戻しており、実応募受付はまだ開始していません。[本番保存経路の検証結果](docs/production-google-verification.md)を参照してください。

Phase 4のGoogle実環境試験は、専用の非公開2ファイル・応募試験タブ・独立Apps Scriptで実施しました。架空データの保存・読込・編集・回復と3保存先の照合を確認済みです。専用APIは試験後に停止し、停止後の保存・更新拒否とデータ保持を再確認しました。[検証記録](docs/phase4-google-verification.md)を参照してください。

Phase 5は、重複判定の基本3項目を確定し、架空データだけを使うローカル重複チェックを試作しました。同じフォーム内と保存済み応募の候補を確認でき、一方のIDだけの一致も保存を保留します。[採用判断](docs/phase5-design-proposal.md)と[検証記録](docs/phase5-local-verification.md)を参照してください。本番保存処理へ統合し、Google実環境で両IDが一致する別新規送信を保存前に拒否することも確認済みです。

再開後、全応募形式の実保存・内容照合と、保存後に応答が切断された場合の再確認を検証しました。2026-10-08にGoogle側の受付停止も確認済みです。試験APIは停止中です。[検証記録](docs/phase3-verification.md)に結果と残る制限事項をまとめています。

2026-10-07：**Phase 3の試験保存を接続・検証済み**。所有者がApps Scriptを配備し、ローカル設定後に架空データの実保存・再送・同時送信・不正入力拒否と、フォームの成功表示を確認しました。残る検証と境界は [試験保存の設定](docs/apps-script-setup.md) を参照してください。本番応募受付は開始していません。

## ローカルでの確認

Phase 4のプレビューは開発サーバーの `/?phase4` です（通常のポートなら `http://127.0.0.1:5173/?phase4`）。Googleへの保存とは分離し、サーバーのメモリだけに架空データを保持します。再起動で消える試験用です。

Phase 5のローカルプレビューは `/?phase5`（通常は `http://127.0.0.1:5173/?phase5`）です。Phase 4とは別のサーバーメモリを使い、Googleへ送信しません。架空データだけで確認してください。

本番公開前の文言・操作プレビューは `/?production-preview`（通常は `http://127.0.0.1:5173/?production-preview`）です。情報取扱い、編集コード保存、受付・編集、重複案内をローカルメモリで確認します。Googleへ送信せず、正式応募にはなりません。本番保存経路の実環境試験は完了しました。Cloudflare Workers + Static Assetsの本番サイトUIと同一オリジン `/api/entry` はローカル実装・検証済みで、Cloudflare実環境への接続と受付開始はまだ行っていません。

Google連携の試験画面は `/?phase4=google` です。試験APIは停止中で、新規保存・更新はできません。再開には運営による新たな試験判断と期限・設定の確認が必要です。本番受付の画面ではありません。

依存導入にはユーザー承認が必要です。導入済みの場合は `npm run dev` で起動し、表示されたローカルURLを開きます。`npm run build` は型チェックと通常ビルド、`npm run preview` はビルド結果のローカル確認です。`npm run dev:cloudflare` は本番ビルドとWorkerをローカル起動し、`npm run build:cloudflare` はデプロイせずWranglerのdry-runまで行います。`npm run build:production` はApps Script検証用の `Code.gs`、`Index.html`、`appsscript.json` をローカル生成します。生成コマンドはGoogleへ配備しません。正式公開構成は [Cloudflare本番サイト構成](docs/cloudflare-deployment.md) を参照してください。

`npm run dev` のPhase 3～5画面と `/?production-preview` は動作確認用です。架空データを使用してください。Cloudflare用の本番ビルドは正式応募向け文言を表示しますが、Apps Scriptの `PRODUCTION_ENABLED=false` を維持しているため実応募はまだ受け付けません。キラー選択肢には、Vol.1のキラー別カードを参照してスカルマーチャントを除いた大会指定の43体を反映済みです。

`npm test` で入力条件・確認データの除外処理のテストを実行できます（Node.js 24環境で検証）。承認された入力ルールの比較用ページは `phase2-preview.html` に残しています。

デザインは、確認済みのふろぐCup Vol.1資料から構造・雰囲気・UI設計思想を参考にした派生デザインです。暗色・スマホ優先・可読性を共有し、主要アクセントはエントリーシステムの識別性を持たせるため緑とします。既存Vol.1のコーラル系アクセントは継承しません。

仕様の正本と未確定事項は [docs索引](docs/README.md)、見た目の方針は [DESIGN.md](DESIGN.md)、作業ルールは [AGENTS.md](AGENTS.md) を参照してください。実装は各フェーズの範囲と未確定事項を確認した後に進めます。
